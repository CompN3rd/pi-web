Durable agent work

Schedule fresh Pi sessions. Keep control of every run.

Automations is a bundled, machine-specific PI WEB plugin that schedules durable workspace jobs in the long-lived session daemon and exposes them through a public-API browser panel.

Create, test, then enable

Select a machine, project, and workspace, then open Automations. New definitions are saved disabled. Use Run now / test and wait for that exact revision to complete before enabling its schedule.

Editing the prompt, trigger, model, thinking policy, timeout, or other definition fields creates a new revision, pauses it, and requires another successful manual test. Every run receives a fresh Pi session without conversational context from another run. The current project and workspace are revalidated before the session starts.

Bundled plugin: plugin id automations, browser API v2, server API v1, and machineSpecific: true. It is included and enabled by default with PI WEB.

Triggers, models, and thinking

  • Manual: run only on demand.
  • One time: run once at a future timestamp.
  • Interval: use a cadence of at least one minute.
  • Cron: use a six-field expression and an explicit IANA time zone.

The same definition never overlaps itself: a colliding scheduled occurrence is recorded as skipped. Choose the machine default or a fixed model, then a supported thinking level. Fixed models are validated again when the session is created and are never silently replaced. History preserves configured and actual model/thinking values.

Timeouts, cancellation, and force-stop

The default timeout is 60 minutes and can be set from 1 minute through 24 hours. Its deadline begins when the fresh session is ready and prompt execution starts, not while a run waits in the queue.

Cancellation intent is stored before PI WEB requests a cooperative abort. If the run does not settle within 15 seconds, the plugin force-stops its leased runtime. The outcome becomes unknown when termination cannot be proven. Cancellation cannot undo external effects that already completed.

Run history and root-session usage

The panel shows recent status, source, revision, times, duration, model/thinking values, errors, cancellation reasons, and root-session token usage. Estimated cost appears only when available; unknown cost remains unknown rather than becoming zero. Root totals do not claim to include untracked subagents or external paid tools.

Session IDs are shown for diagnosis, but direct history links are omitted until PI WEB exposes a public plugin navigation helper. The plugin does not construct private session URLs. Deleting a definition retains its run history.

Daemon-owned persistence and recovery

The long-lived session daemon owns the scheduler and stores definitions, revisions, occurrences, attempts, cancellation, and usage in:

$PI_WEB_DATA_DIR/plugin-state/automations/automations.sqlite

The data directory defaults to ~/.pi-web. Its one ownership marker is the global $PI_WEB_DATA_DIR/sessiond-owner.json; Automations creates no separate owner file.

Browser disconnects, page reloads, and web/API restarts do not stop the scheduler or active runs. The panel polls the paired backend about every 2 seconds while work is active and every 15 seconds while idle; there is no Automations-specific realtime protocol.

After an unexpected daemon restart, queued work remains eligible, while starting, running, or cancelling attempts become unknown and are not blindly repeated. Definitions, history, and future schedule state remain durable.

Server-plugin/runtime changes require a manual target-daemon restart followed by a browser reload. For the systemd user service, run systemctl --user restart pi-web-sessiond. Restarting only the web/API process or using Pi's /reload does not activate changed server code.

Local and remote machines

Automations uses PI WEB's generic plugin federation. For a remote selection, the remote machine's compatible plugin supplies the panel through the gateway while its session daemon validates the workspace, stores the SQLite database, resolves models, schedules work, and runs sessions locally.

Definitions are not replicated and do not fail over. Recreate a definition on a destination machine so that machine can validate it. A gateway or browser disconnect does not stop work owned by a still-running remote daemon.

Enable, disable, and recover

Use Settings → PI WEB plugins or the standard global plugin config. It has no separate core config key.

{
  "plugins": {
    "automations": { "enabled": false }
  }
}

Restart the target session daemon and reload the browser after changing this server-backed plugin. Disabling preserves its database. Standard offline recovery also applies, including pi-web plugins disable automations --restart.

Security boundary

Plugins are trusted code. The browser entry runs in the PI WEB page, and the server entry runs in-process with sessiond. A fresh session isolates conversation context, not the host: prompts and tools retain the target machine's Pi and OS-user permissions. Review prompts, use least-privilege credentials, and protect PI WEB with authentication and network controls.

The panel uses public context.backend.request(), and the server uses PI WEB's public plugin lifecycle and background-session lease. It adds no Automations-specific core route.
